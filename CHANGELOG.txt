SK MOBILES CHANGELOG

VERSION V5.4 DATA-PERSISTENCE-LOCK

BEFORE:
- Opening Bill History could auto-save the current form.
- Closing the billing modal could auto-save a partially completed bill.
- beforeunload could write stale in-memory savedBills back to localStorage.
- Bill History had a repair layer that could merge stale in-memory bills back into persistent storage.
- Firebase login/realtime listener could pull an older cloud snapshot over a local delete/edit.
- Firestore chunk documents could remain after a key was replaced/deleted, allowing stale data to return.

MODIFIED:
1. Bill persistence is now explicit: Save Bill / Update Bill / Payment / Delete are the write actions.
2. History tab is read-only navigation and no longer saves the form.
3. Closing the billing modal saves only the draft, not a bill.
4. Removed beforeunload persistence of savedBills.
5. Bill History reads persisted sk_bills as the source of truth and never merges stale memory back.
6. Firebase authority model:
   - First empty device may restore cloud data once.
   - Once initialized, local business data is authoritative.
   - Automatic sync is local -> cloud.
   - Cloud -> local is explicit Restore Cloud Data only.
7. Authoritative cloud sync deletes stale Firestore data documents and old chunk documents before writing the current local snapshot.
8. Key-level cloud sync removes stale chunk documents when a key is deleted or changes size.
9. Realtime business-data listener is disabled to prevent deleted/edited records from being resurrected.

NOT MODIFIED:
- index.html UI structure
- css/style.css
- existing business fields/storage keys
- customer/bill/repair data formats unless required for persistence safety

VALIDATION:
- JavaScript syntax checked with Node --check.
- index.html and css/style.css retained from the uploaded base project.

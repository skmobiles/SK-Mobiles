SK MOBILES V6 — DEVELOPMENT RULES

1. This is a clean rewrite. Do not copy old V4/V5 patch scripts into this project.
2. Keep exactly three application code files:
   - index.html
   - css/style.css
   - js/app.js
3. Keep all business data in the single V6 local state key: skm_v6_state.
4. Bills are the source of truth for credit and EMI. Do not create a second credit ledger that duplicates bill amounts.
5. Payments belong to a bill and each payment has one unique receipt ID.
6. Delete must update persisted state before rendering. Never restore deleted records automatically.
7. History opening, modal closing and page refresh must never save a draft automatically.
8. Edit must update the same Bill ID and must not create a second bill.
9. Do not add Firebase/cloud restore without an explicit migration design and conflict policy.
10. Any future feature must be added to the existing clean modules rather than appending another patch layer.
